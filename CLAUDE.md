# rwcli

CLI для панели Remnawave поверх `rw-sdk`. Весь код — один модуль `rwcli.py`
(точка входа `rwcli:main`, команда `rwcli`). Имя проекта и команды — `rwcli`,
слитно (не `rw-cli`, не `rw_cli`).

## Правила работы (важно)

1. Никаких изменений в коде/файлах без явного разрешения пользователя. Вопрос
   («можешь?», «как сделать?», «почему так?») — это не разрешение: ответить,
   предложить план и ждать «делай».
2. Простота — одна из главных ценностей проекта. Если задача влечёт заметные
   переделки, новые зависимости, абстракции или усложнение — предупредить
   заранее и предложить более простой вариант.
3. Если задача кажется странной (излишне сложной, ухудшающей код/UX, такой,
   что не понравилась бы опытному программисту) — сказать об этом до работы.

## Окружение и проверка

```bash
uv venv .venv && uv pip install --python .venv/bin/python -e '.[test]'
.venv/bin/pytest            # тесты, без сети (клиент Remnawave мокается)
.venv/bin/rwcli --help
```

После любых изменений в `rwcli.py` — прогнать `.venv/bin/pytest`.

## Безопасность

- `.env` содержит настоящий `API_TOKEN` к рабочей панели: не читать, не
  выводить, не коммитить.
- Не запускать команды против реальной панели без явной просьбы. `create` и
  `delete` меняют боевые данные — только с подтверждения пользователя.
- В примерах и docstring использовать `rw.example.com`, не реальные адреса.

## Соглашения

- Интерфейс (сообщения, help, ошибки), комментарии в коде и README — на
  английском. CLAUDE.md — на русском.
- Без новых runtime-зависимостей кроме `rw-sdk` (стандартная библиотека).
- Ошибки API обрабатываются декоратором `die_on_api_error`; ошибки ввода —
  `sys.exit("сообщение")`.
- Режим `users -f` — стабильный машиночитаемый TSV-формат: не менять вывод
  существующих полей без необходимости.
- При добавлении/изменении команд или флагов обновлять README.md.
